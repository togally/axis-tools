# Axis v0.2 Contract

## Status

Axis v0.2 is the active and default package contract. Axis v0.1 is expired for normal configuration, capture, report, and publish commands. Historical v0.1 configuration remains readable only through the migration inspection flow.

## Project Configuration

Configure a target repository through the conversational `axis-doc-project-init` Skill. The Skill requests the repository path, runs `project-init --inspect --json`, and presents every stored or migrated field one by one. Existing values are shown for confirmation, and selector changes rebind the organization and OSS profile before the final confirmation.

The deterministic CLI boundary is:

```text
axis project-init --repo <path> --inspect --json
axis project-init --repo <path> --answers-file <path> --apply
axis project-init --repo <path> --recover
```

The answers file contains inspection fingerprints, ordered decisions, and a final confirmation. Credentials are never collected. The Skill recommends environment variable names, checks whether those names are present, and prints shell export commands containing names only when values are missing. Apply stops until the user sets the variables and confirms again.

The active main config references an organization registry and an OSS profile:

```yaml
contract_version: "0.2"
organization:
  id: org_example
  registry: .axis/organizations.yml
oss:
  provider: aliyun-oss
  profile: private_beta_main
```

The registry stores public-safe bucket, prefix, and environment variable names. Secret values must remain in the user's shell or secret manager.

## Migration

Every new protocol version must ship a versioned mapping from its immediate predecessor, for example `protocols/migrations/0.1-to-0.2.yml`. A stored older protocol is migrated one adjacent version at a time until it reaches the latest version. Each step records provenance and unresolved prompts. The user confirms the resulting latest-version fields before apply.

Unsupported legacy values are displayed as redacted removal decisions. The migration engine never evaluates mapping code and never emits credential values.

## Packages

Active packages use `.axis/outbox/v0.2/<organization_id>/<project_slug>/<run_id>/`. Manifests and metadata declare protocol versions `0.2` and include organization, project, OSS profile, release, checksum, and public-safety snapshots.

`axis validate-config`, `axis coding-capture`, `axis test-report`, and `axis oss-publish` reject v0.1 with a stable migration message. Use inspection and confirmed answers to move a repository to v0.2 first.

## Transaction and Recovery

Apply validates the generated configuration before writing, records a journal, replaces files with backups, rereads and validates the result, and removes the journal only after success. If a journal remains, inspection reports recovery required. Run `project-init --recover` before another apply.
