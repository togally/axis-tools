# Axis Tools v0.1 Contract

## Design Conclusion

v0.1 defines one public-safe local package contract: skills write a fixed package under `.axis/outbox/`, and `axis-oss-publish` uploads that package to Aliyun OSS using credentials read only from environment variables. The uploaded `manifest.json` is the source of truth for the package; v0.1 does not include management surfaces, indexing services, permission systems, or asset lifecycle administration.

## Business Design

### Scope

v0.1 targets only:

- public package creation from local skill output;
- committed public project configuration in `.axis/config.yml`;
- local-only overrides in `.axis/config.local.yml`;
- local-only package staging in `.axis/outbox/`;
- Aliyun OSS upload of public-safe package files;
- four v0.1 skill contracts:
  - `axis-project-init`;
  - `axis-coding-capture`;
  - `axis-test-report`;
  - `axis-oss-publish`.

### Public-Safe Rule

Every file that can be uploaded to OSS must be safe to publish. v0.1 packages must not contain credentials, private hostnames, private repository URLs, customer names, internal ticket URLs, personal tokens, raw environment dumps, or unredacted logs.

Secrets are read only from environment variables. Neither `.axis/config.yml`, `.axis/config.local.yml`, `manifest.json`, `metadata.json`, `report.md`, nor `experience.md` may contain secret values.

### Local-Only Rule

The following paths are local-only and must not be committed or uploaded as directories:

- `.axis/config.local.yml`;
- `.axis/outbox/`.

`axis-project-init` may create or validate ignore rules for those paths, but v0.1 does not require a repository-wide policy engine.

### Package Lifecycle

The package lifecycle has four states:

| State | Owner | Meaning | Terminal |
| --- | --- | --- | --- |
| `local_ready` | producing skill | Required files exist under `.axis/outbox/` and have passed public-safety checks. | no |
| `uploading` | `axis-oss-publish` | Upload is in progress. Partial remote objects may exist. | no |
| `published` | `axis-oss-publish` | All package files are uploaded and the remote `manifest.json` is uploaded last. | yes |
| `failed` | producing skill or `axis-oss-publish` | Local validation or upload failed. Failure details stay local unless the user manually includes public-safe details in a later package. | yes |

The remote `manifest.json` must be uploaded last. Consumers may treat a package as readable only after `manifest.json` exists at the final OSS path.

### Non-Goals

v0.1 explicitly does not include:

- management pages, service APIs, admin consoles, or asset management workflows;
- database schemas, search indexing, dashboards, or package catalog services;
- user, team, role, approval, or permission management;
- private artifact storage or private-source upload;
- multi-cloud publishing;
- OSS bucket creation, credential provisioning, or RAM policy management;
- remote deletion, retention, archive, or lifecycle automation;
- automatic public-safety guarantees beyond deterministic local validation and explicit field restrictions.

## Technical Design

### Repository Paths

Committed path:

```text
.axis/config.yml
```

Local-only paths:

```text
.axis/config.local.yml
.axis/outbox/
```

Local outbox layout:

```text
.axis/outbox/
  v0.1/
    demo-project/
      20260703T121530Z-test-report-a1b2c3d4/
        manifest.json
        metadata.json
        report.md
        experience.md
```

The package directory name is the `run_id`. v0.1 package directories contain exactly the four required files above.

### `.axis/config.yml`

`.axis/config.yml` is committed project configuration. It contains public, reusable settings only.

Required fields:

| Field | Type | Rule |
| --- | --- | --- |
| `contract_version` | string | Must be `"0.1"`. |
| `project.slug` | string | Lowercase slug matching `^[a-z0-9][a-z0-9-]{1,62}$`. |
| `project.display_name` | string | Public display name. |
| `package.outbox_dir` | string | Must be `.axis/outbox` for v0.1. |
| `package.visibility` | string | Must be `public` for v0.1. |
| `oss.provider` | string | Must be `aliyun-oss`. |
| `oss.bucket` | string | Public-safe bucket name. |
| `oss.prefix` | string | Public-safe prefix without leading or trailing slash. |
| `oss.endpoint_env` | string | Environment variable name for the OSS endpoint. |
| `oss.region_env` | string | Environment variable name for the OSS region. |
| `oss.access_key_id_env` | string | Environment variable name for the access key ID. |
| `oss.access_key_secret_env` | string | Environment variable name for the access key secret. |
| `oss.security_token_env` | string | Environment variable name for an optional STS token. |
| `skills.project_init` | string | Must be `axis-project-init`. |
| `skills.coding_capture` | string | Must be `axis-coding-capture`. |
| `skills.test_report` | string | Must be `axis-test-report`. |
| `skills.oss_publish` | string | Must be `axis-oss-publish`. |

Complete YAML example:

```yaml
contract_version: "0.1"
project:
  slug: demo-project
  display_name: Demo Project
package:
  outbox_dir: .axis/outbox
  visibility: public
oss:
  provider: aliyun-oss
  bucket: axis-public-packages-example
  prefix: axis/v0.1/packages
  endpoint_env: ALIYUN_OSS_ENDPOINT
  region_env: ALIYUN_OSS_REGION
  access_key_id_env: ALIYUN_OSS_ACCESS_KEY_ID
  access_key_secret_env: ALIYUN_OSS_ACCESS_KEY_SECRET
  security_token_env: ALIYUN_OSS_SECURITY_TOKEN
skills:
  project_init: axis-project-init
  coding_capture: axis-coding-capture
  test_report: axis-test-report
  oss_publish: axis-oss-publish
```

### `.axis/config.local.yml`

`.axis/config.local.yml` is local-only runtime configuration. It may override non-secret local behavior, but it must not contain credential values.

Allowed fields:

| Field | Type | Rule |
| --- | --- | --- |
| `contract_version` | string | Must be `"0.1"`. |
| `local.outbox_dir` | string | Defaults to `.axis/outbox`. |
| `local.dry_run` | boolean | If `true`, `axis-oss-publish` validates but does not upload. |
| `local.redaction_patterns_file` | string | Local-only file path for additional redaction patterns. |
| `oss.endpoint_env` | string | Optional override for endpoint environment variable name. |
| `oss.region_env` | string | Optional override for region environment variable name. |
| `oss.access_key_id_env` | string | Optional override for access key ID environment variable name. |
| `oss.access_key_secret_env` | string | Optional override for access key secret environment variable name. |
| `oss.security_token_env` | string | Optional override for STS token environment variable name. |

Complete YAML example:

```yaml
contract_version: "0.1"
local:
  outbox_dir: .axis/outbox
  dry_run: true
  redaction_patterns_file: .axis/redaction.local.txt
oss:
  endpoint_env: ALIYUN_OSS_ENDPOINT
  region_env: ALIYUN_OSS_REGION
  access_key_id_env: ALIYUN_OSS_ACCESS_KEY_ID
  access_key_secret_env: ALIYUN_OSS_ACCESS_KEY_SECRET
  security_token_env: ALIYUN_OSS_SECURITY_TOKEN
```

### OSS Path Convention

OSS object keys use this fixed shape:

```text
{oss.prefix}/{project.slug}/{run_id}/{file_name}
```

`run_id` format:

```text
YYYYMMDDThhmmssZ-{producer_short_name}-{8_lower_hex}
```

Complete OSS path example:

```text
oss://axis-public-packages-example/axis/v0.1/packages/demo-project/20260703T121530Z-test-report-a1b2c3d4/manifest.json
```

Complete package object set for the same run:

```text
oss://axis-public-packages-example/axis/v0.1/packages/demo-project/20260703T121530Z-test-report-a1b2c3d4/manifest.json
oss://axis-public-packages-example/axis/v0.1/packages/demo-project/20260703T121530Z-test-report-a1b2c3d4/metadata.json
oss://axis-public-packages-example/axis/v0.1/packages/demo-project/20260703T121530Z-test-report-a1b2c3d4/report.md
oss://axis-public-packages-example/axis/v0.1/packages/demo-project/20260703T121530Z-test-report-a1b2c3d4/experience.md
```

### `manifest.json`

`manifest.json` is the package source of truth. It lists every file, checksum, package identity, producer skill, and publish location.

Required fields:

| Field | Type | Rule |
| --- | --- | --- |
| `schema` | string | Must be `axis.package.manifest`. |
| `schema_version` | string | Must be `"0.1"`. |
| `package_id` | string | Must be `{project.slug}__{run_id}`. |
| `created_at` | string | UTC ISO-8601 timestamp. |
| `project.slug` | string | Copied from `.axis/config.yml`. |
| `project.display_name` | string | Copied from `.axis/config.yml`. |
| `producer.skill` | string | One v0.1 skill name. |
| `producer.agent` | string | Public-safe agent/runtime family name. |
| `run.run_id` | string | Directory name and OSS path segment. |
| `run.git.branch` | string | Public-safe branch name or `unknown`. |
| `run.git.commit` | string | Full 40-character SHA or `unknown`. |
| `run.git.dirty` | boolean | Whether local uncommitted changes existed while packaging. |
| `files` | array | Exactly four entries: metadata, report, experience, manifest. |
| `publish.provider` | string | Must be `aliyun-oss`. |
| `publish.status` | string | `local_ready`, `published`, or `failed`. |
| `publish.bucket` | string | Copied from config. |
| `publish.prefix` | string | Copied from config. |
| `publish.base_uri` | string | OSS URI ending with `/`. |

Complete JSON example:


### `metadata.json`

`metadata.json` is the compact machine-readable summary for future discovery. It must remain public-safe and must not duplicate full report content.

Required fields:

| Field | Type | Rule |
| --- | --- | --- |
| `schema` | string | Must be `axis.package.metadata`. |
| `schema_version` | string | Must be `"0.1"`. |
| `title` | string | Public-safe package title. |
| `summary` | string | Public-safe summary, maximum 500 characters. |
| `tags` | array | Lowercase public-safe tags. |
| `artifact.type` | string | `coding_capture`, `test_report`, or `project_init`. |
| `artifact.status` | string | `passed`, `failed`, `partial`, or `informational`. |
| `artifact.started_at` | string | UTC ISO-8601 timestamp. |
| `artifact.finished_at` | string | UTC ISO-8601 timestamp. |
| `skill.name` | string | One v0.1 skill name. |
| `skill.responsibility` | string | Public-safe skill responsibility summary. |
| `public_safety.reviewed` | boolean | Must be `true` before publishing. |
| `public_safety.contains_credentials` | boolean | Must be `false` before publishing. |
| `public_safety.contains_private_urls` | boolean | Must be `false` before publishing. |
| `public_safety.redaction_notes` | string | Public-safe note describing the redaction result. |
| `links.manifest_path` | string | Must be `manifest.json`. |
| `links.report_path` | string | Must be `report.md`. |
| `links.experience_path` | string | Must be `experience.md`. |

Complete JSON example:

```json
{
  "schema": "axis.package.metadata",
  "schema_version": "0.1",
  "title": "Demo Project Test Report",
  "summary": "Public-safe validation report for the demo-project package contract.",
  "tags": ["axis-tools", "test-report", "public-safe"],
  "artifact": {
    "type": "test_report",
    "status": "passed",
    "started_at": "2026-07-03T12:10:00Z",
    "finished_at": "2026-07-03T12:15:30Z"
  },
  "skill": {
    "name": "axis-test-report",
    "responsibility": "Run configured validation commands and write a public-safe report."
  },
  "public_safety": {
    "reviewed": true,
    "contains_credentials": false,
    "contains_private_urls": false,
    "redaction_notes": "No credentials, private URLs, or customer-specific identifiers were found."
  },
  "links": {
    "manifest_path": "manifest.json",
    "report_path": "report.md",
    "experience_path": "experience.md"
  }
}
```

### `report.md`

`report.md` is the human-readable result report. It must use this section order:

```markdown
# Report

## Summary
## Scope
## Commands
## Result
## Evidence
## Public Safety
## Limitations
## Next Actions
```

Rules:

- `Commands` lists public-safe commands only; redact local paths or tokens if needed.
- `Evidence` summarizes evidence instead of pasting raw private logs.
- `Public Safety` states whether the report was reviewed and what was redacted.
- `Next Actions` must not assign management-surface work to v0.1.

### `experience.md`

`experience.md` captures reusable implementation experience. It must use this section order:

```markdown
# Experience

## Context
## Decision
## Steps
## Validation
## Reuse Notes
## Public Safety
```

Rules:

- `Context` describes the reusable technical situation without private project facts.
- `Decision` states the selected approach.
- `Steps` describes repeatable steps, not a transcript.
- `Validation` lists checks that proved the outcome.
- `Reuse Notes` explains when future agents should reuse the experience.
- `Public Safety` states the sanitization result.

### Skill Boundaries

| Skill | Owns | Does Not Own |
| --- | --- | --- |
| `axis-project-init` | Create `.axis/config.yml`, create local `.axis/` structure, validate local-only path rules, and explain required environment variables. | Credential creation, OSS bucket creation, management surfaces, or publishing package content. |
| `axis-coding-capture` | Convert coding work into `experience.md`, update `metadata.json` for `coding_capture`, and stage a public-safe local package. | Running test suites as the authoritative test report, uploading to OSS, or indexing packages. |
| `axis-test-report` | Run configured validation commands, write `report.md`, update `metadata.json` for `test_report`, and stage a public-safe local package. | Fixing product code by default, publishing to OSS, or managing remote package catalogs. |
| `axis-oss-publish` | Read config, validate package files and checksums, read OSS credentials from environment variables, upload files to Aliyun OSS, and upload `manifest.json` last. | Creating credentials, creating buckets, building management APIs, search indexing, or deleting remote packages. |

### Idempotency and Consistency

- `package_id` is unique for one project slug and run ID.
- Re-running a producing skill with the same `run_id` must overwrite only the matching local package directory.
- `axis-oss-publish` treats an existing remote object with the same SHA-256 as success.
- `axis-oss-publish` treats an existing remote object with a different SHA-256 as a failure in v0.1.
- The uploaded `manifest.json` is the remote source of truth.
- Package discovery must not depend on local `.axis/outbox/` after publishing.

### Validation Requirements

Before a package reaches `local_ready`, the producing skill must verify:

- all four required files exist;
- JSON files parse successfully;
- `schema_version` is `"0.1"`;
- file paths in `manifest.json` are relative file names, not absolute paths;
- checksums and byte counts match local files;
- public-safety fields in `metadata.json` allow publishing.

Before a package reaches `published`, `axis-oss-publish` must verify:

- required OSS environment variables are present;
- `.axis/config.local.yml` and `.axis/outbox/` are not uploaded as directories;
- every object upload succeeds;
- `manifest.json` is uploaded last;
- remote URI values match the configured bucket, prefix, project slug, and run ID.

### Phase-Two Indexing Note

Phase two may build indexing over OSS assets. v0.1 only prepares stable public-safe fields for that future phase:

- `schema_version`;
- `package_id`;
- `created_at`;
- `project.slug`;
- `producer.skill`;
- `artifact.type`;
- `artifact.status`;
- `tags`;
- `publish.base_uri`.

Phase-two systems should index uploaded `manifest.json` and `metadata.json` from OSS. They must treat v0.1 packages as immutable published records and add new optional fields through a later schema version instead of changing v0.1 required fields. Management surfaces over that index belong outside this v0.1 contract and are not specified here.

### Compatibility

v0.1-compatible changes may add optional fields that consumers can ignore. Changes that rename required fields, change path layout, change package lifecycle states, or change the four required file names require a new contract version.
